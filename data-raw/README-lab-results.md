# Synthetic COVID-19 lab-result feed

**This data is fake.** No row describes a real person, provider, or laboratory.
The laboratory names, CLIA numbers, NPIs, specimen IDs, accession numbers,
patient names and MRNs are all invented. What *is* real is the vocabulary —
the LOINC, SNOMED CT and ICD-10-CM codes are the genuine published codes,
because the whole point is to practice on data that looks like the real feed.

Generated by `data-raw/make-synthetic-lab-results.R`.

```bash
just lab-data                # 25,000 rows -> data/synthetic-covid-lab-results.csv
just lab-data 5000000        # ~3 GB of CSV
just lab-data-messy          # -> data/synthetic-covid-lab-results-messy.csv
just lab-data-parquet        # the same feed, partitioned parquet
```

Two files ship in `data/`, generated from the same seed, so the 25,000 base
results line up one-to-one on `specimen_id` — same patients, same diagnosis
codes, same underlying results — with the messy one put through the
sender-quirk layer described at the bottom of this file. (Only the *resends*
differ between the two, since the quirk layer draws from the same random
stream that picks which messages get re-sent.)

| file | use |
| --- | --- |
| `synthetic-covid-lab-results.csv` | ISO timestamps, LOINC codes throughout, one spelling per town. Already has missingness, corrections and multi-code diagnosis fields. |
| `synthetic-covid-lab-results-messy.csv` | Same rows, plus five datetime dialects, non-LOINC local codes, drifting result text and town spellings. |

One row = one test result, shaped the way a flattened HL7 v2 `ORU^R01` feed
lands in a surveillance system. Collection dates span 2020-01-15 to 2021-06-30.

## Why this dataset exists

### 1. The ICD-10 era switch

There was no COVID-19 diagnosis code when the pandemic started. US effective
dates:

| From | Codes available | What a sender actually used |
| --- | --- | --- |
| before 2020-04-01 | no COVID code | `B34.2` (coronavirus infection, unspecified), `B97.29` (other coronavirus as the cause of diseases classified elsewhere), plus symptom codes |
| 2020-04-01 | `U07.1` COVID-19 | mostly `U07.1`, but a long tail of senders kept emitting `B97.29` for months |
| 2021-01-01 | `Z20.822`, `Z11.52`, `J12.82`, `Z86.16`, `M35.81` | screening and exposure encounters finally get their own codes |

The generator reproduces the lag on purpose. `filter(dx_codes == "U07.1")`
silently drops the entire first wave, and about a fifth of the second. Finding
that out is the exercise.

### 2. Scale

Row width is realistic — the LOINC long names alone are ~90 characters and
repeat on every row — so the file grows fast:

| rows | CSV size |
| --- | --- |
| 25,000 | ~16 MB |
| 1,000,000 | ~650 MB |
| 10,000,000 | ~6.5 GB |

That is the wall to hit with `read_csv()` before arrow / duckdb / parquet get
introduced as the answer. The generator writes in chunks, so building a
ten-million-row file never needs ten million rows of memory.

## Columns

| Column | Notes |
| --- | --- |
| `message_control_id` | HL7 MSH-10. Unique per message, **not** per specimen — corrections reuse the specimen and get a new message id. |
| `accession_number` | The lab's internal number for the specimen. |
| `specimen_id` | Format varies **by lab on purpose** — `NRL-20201028-00685`, `4000012345`, `HVH20-000123`. One regex will not parse all of them. |
| `placer_order_number`, `filler_order_number` | Ordering system's and lab's order numbers. |
| `patient_id` | Synthetic linkage key. Real ELR has no such column — it is here so you can check your own deduplication. About 61% of patients have more than one result, and those patients account for ~81% of rows. |
| `patient_last_name`, `patient_first_name`, `date_of_birth` | Fake. Age is not given; derive it from `date_of_birth` and the collection date. |
| `sex` | `F` / `M` / `U`, sometimes missing. |
| `race`, `ethnicity` | CDC-style categories, heavily `Unknown` — as in the real feed. |
| `patient_town`, `patient_county`, `patient_state`, `patient_zip` | The 29 towns of Hartford County, matching `data/synthetic-covid-linelist.csv` so the two can be joined. Town values sometimes carry trailing whitespace. |
| `ordering_facility`, `ordering_provider_npi`, `ordering_provider_name` | NPIs are fake but pass the Luhn check real NPIs must pass. |
| `performing_lab`, `performing_lab_clia` | Eight fictional labs. Lab names show up in mixed case on ~5% of rows. |
| `specimen_collection_dt` | ISO 8601, UTC. Missing on ~1.5% of rows. |
| `specimen_received_dt`, `result_dt`, `reported_to_dph_dt` | Turnaround times stretch during the surges, which is where the reporting-delay lesson lives. |
| `specimen_source_snomed`, `specimen_source` | SNOMED CT (SPM-4). Constrained by assay: antigen only on upper-respiratory specimens, serology only on serum/plasma. |
| `test_ordered_loinc`, `test_ordered_name` | What was ordered (OBR-4) — often a panel. |
| `test_performed_loinc`, `test_performed_name` | What was actually run (OBX-3). Deliberately differs from what was ordered. |
| `test_method` | RT-PCR, Isothermal NAA, Rapid immunoassay, Chemiluminescent immunoassay. |
| `instrument_model` | Fictional analyzers. |
| `result_snomed`, `result_value` | SNOMED-coded result plus its text. Note that PCR reports *Detected / Not detected* while serology reports *Positive / Negative* — counting "positives" means handling both. |
| `result_numeric`, `result_units`, `reference_range` | Serology index values only; `NA` for qualitative tests. |
| `abnormal_flag` | `A` / `N`, missing for invalid and unsatisfactory results. |
| `result_status` | HL7 OBX-11: `F` final, `P` preliminary, `C` corrected. |
| `ct_value` | Cycle threshold. Only on positive amplification tests, and only ~62% of those — plenty of labs never reported it. |
| `dx_codes` | **Pipe-delimited**, one to three ICD-10-CM codes. ~4% of rows have the decimal point stripped (`U071` rather than `U07.1`). |
| `note` | Sparse free text. |

## Deliberate messiness

Every one of these appears in real ELR feeds and each breaks a different naive
pipeline:

- **Resends and corrections** (~1.7% of rows). The same `specimen_id` arrives
  again with a new `message_control_id`, status `C`, a later `result_dt`, and
  a flipped result about a fifth of the time. Deduplicating on `specimen_id`
  alone throws the correction away; keeping everything double-counts.
- **Unusable specimens** (~1.8%): invalid runs, unsatisfactory specimens.
- **Missing values**, concentrated where they really go missing: collection
  date, ZIP, ordering NPI, race, ethnicity.
- **Case and whitespace drift** in lab and town names.
- **Multiple diagnosis codes in one cell**, pipe-delimited.
- **Codes with and without the decimal point.**
- **Rows are not sorted** by anything.

## Sender quirks (`--messy`)

Four more layers, off unless you ask for them. The organizing idea: **a sending
system is not randomly messy, it is reliably messy in one particular way.**
Somebody configured an interface engine once in 2020 and nobody has touched it
since. So the datetime format, the result wording and the code system are
properties *of the lab*, consistent across all of its rows — which means they
can be handled, once you notice. The town spellings are the exception, because
those come from a person at a keyboard rather than an interface engine, so they
wobble row by row even for the same patient.

Turn on all four with `--messy`, or pick with `--messy-parts dates,towns,codes,text`.

### `dates` — five datetime dialects

Each lab writes all four of its timestamp columns one way:

| Lab | Format | Example |
| --- | --- | --- |
| Nutmeg Regional, State PHL | ISO 8601 | `2021-01-07T12:41:11Z` |
| Charter Oak | HL7 TS with offset | `20200519125909-0400` |
| Housatonic Valley, Farmington River | Excel-ish | `2021-02-15 15:08:01` |
| Quinnipiac, Bramblebush | US, zeros stripped | `2/13/2021 1:43 PM` |
| Sound Shore | **date only** | `02/14/2021` |

The offset on the HL7 format tracks EST/EDT correctly, so the DST boundary is
in there too. Sound Shore's times are simply gone — no parser recovers them,
and deciding what to do about that sender is the exercise.

### `towns` — geography that will not standardize

- Case and abbreviation drift **per row**: `West Hartford`, `W. Hartford`,
  `WEST HARTFORD`, `west hartford`, `West Hartfrod` (transposed letters),
  trailing spaces. The same patient turns up spelled three ways across three
  visits, so grouping on the raw string splits one person into three.
- ~2% of patients live **outside Hartford County**, including out of state —
  New Haven, Bridgeport, Springfield MA, Westerly RI. Their `patient_county`,
  `patient_state` and ZIP follow (a Massachusetts ZIP starts `010xx`, not
  `06xxx`), so a rate denominator built from Hartford County towns is wrong
  in a way that will not show up as an error.
- `patient_state` arrives as `CT`, `ct`, or `Connecticut`.

### `codes` — local compendium codes before LOINC onboarding

Three labs send their own LIS codes until **2020-09-01**, then switch to LOINC:

| Lab | PCR | Antigen | Serology |
| --- | --- | --- | --- |
| Charter Oak | `30412` | `30455` | `30987` |
| Quinnipiac | `COVIDPCR` | `COVIDAG` | `COVIDABPNL` |
| Bramblebush | `BUC-COV19-NAA` | `BUC-COV19-AG` | `BUC-COV19-AB` |

Both `test_ordered_loinc` and `test_performed_loinc` carry the local code, so
joining to a LOINC lookup silently drops those rows for the first half of the
series. The cutover is the *sender's*, not the pandemic's, so it lands
mid-series with no external event to explain it.

### `text` — the same result written four ways

`result_snomed` stays correct throughout. `result_value` does not:

| Style | Detected | Not detected |
| --- | --- | --- |
| standard | `Detected` | `Not detected` |
| shout | `DETECTED` | `NOT DETECTED` |
| abbrev | `POS` | `NEG` (also `IND`, `INV`, `QNS`) |
| verbose | `Positive for SARS-CoV-2 (COVID-19) by RT-PCR` | `No SARS-CoV-2 (COVID-19) RNA detected` |

And on ~8% of rows `result_snomed` is blank, so the free text is the only thing
left to go on. The lesson is the obvious one: count on the code, not the text —
except where the code is missing, and then you have to parse the text anyway.

## Determinism

Fixed seed, and patient attributes are derived arithmetically from the patient
id rather than stored, so the same id yields the same person in every chunk and
at every `--rows`. Re-running with the same arguments reproduces the file
exactly. `--seed` changes the cohort. The clean and messy files come off the
same seed, so they are the same results with and without the quirk layer.

The id-to-attribute hash is a two-round multiply-and-xorshift rather than the
obvious Lehmer step, because a plain modular multiply is *linear*: every salt
would produce the same sequence shifted by a constant, and "town" and "race"
would be perfectly correlated draws. Two rounds bring the cross-salt
correlation down to ~0.007.

## Flags

| Flag | Default | Meaning |
| --- | --- | --- |
| `--rows` | `25000` | Rows to generate (before resends, which add ~1.7%). |
| `--out` | `data/synthetic-covid-lab-results.csv` | Output path. For parquet, a directory. |
| `--format` | `csv` | `csv` or `parquet`. |
| `--seed` | `20200401` | The day `U07.1` went live. |
| `--chunk` | `250000` | Rows generated and written per pass. |
| `--messy` | off | Turn on all four sender-quirk layers. |
| `--messy-parts` | all four | Comma-separated subset: `dates`, `towns`, `codes`, `text`. |
