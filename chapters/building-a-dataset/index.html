6  Building a Dataset

Packages covered in this part: dplyr, tidyr, readr, janitor, stringr, lubridate

Every dataset so far has been a count table: one row per town per report date, with cumulative cases and deaths. That’s what the state publishes, and it’s plenty for trends and maps. But a lot of everyday epi work happens one level down — at the case level. How old were the people who got sick? How long between symptom onset and a positive report? What share of hospitalized patients died, and did that differ by age?

None of those questions can be answered from a count table, because the individual people have already been summed away. To practice case-level work you need a line-list: one row per case, with that person’s age, dates, and outcomes.

Real line-lists exist — but they’re confidential. You can’t paste real patients into a public book. So this chapter does the next best thing: it manufactures a fake line-list from the real counts, and the act of building it is the lesson. It also means stepping away from the town-level Commissioner briefing for a chapter or two — the real town data resumes in the Data Visualization chapter — while we drop down to the case level, where a safe-to-share synthetic dataset is the only honest option. Along the way you’ll expand a count table into individual rows, invent plausible values with controlled randomness, recode and categorize variables, and do arithmetic on dates — the core moves of data manipulation.

WarningThis data is fake

synthetic-covid-linelist.csv is synthetic. The town names and the number of cases per town are real (from the CT Open Data Portal), but every age, sex, race/ethnicity, date, hospitalization, and death is randomly generated. No row is a real person. It exists only to practice on — never analyze it as if it were real, and never mix it into real reporting.

6.1 The plan

We’ll scope the work to Hartford County during the winter 2020–2021 surge (December 2020 through January 2021) — a real wave, before vaccines were widely available, and a chunk of data small enough to build on a laptop. The recipe has three moves:

  1. Start from the real town counts and work out how many new cases each town had on each report date.
  2. Expand those counts into one row per case.
  3. Attach invented-but-plausible demographics and outcomes to each row.

6.2 Part A — How the line-list was built

The full recipe lives in data-raw/make-synthetic-linelist.R in the book’s repository. We’ll walk through it a piece at a time. You don’t need to run it yourself — the finished file is in the Data Library — but reading it teaches the moves.

6.2.1 Real counts into new cases

Total cases is cumulative, so a town’s new cases on a given day are the change from its previous report — the same lag() trick from earlier chapters. We floor negatives at zero (the state sometimes revises an old total downward, and you can’t have negative people), then keep only our county and our two-month window.

hartford_county <- c(
  "Avon",
  "Berlin",
  "Bloomfield",
  "Bristol",
  "Burlington",
  "Canton",
  "East Granby",
  "East Hartford",
  "East Windsor",
  "Enfield",
  "Farmington",
  "Glastonbury",
  "Granby",
  "Hartford",
  "Hartland",
  "Manchester",
  "Marlborough",
  "New Britain",
  "Newington",
  "Plainville",
  "Rocky Hill",
  "Simsbury",
  "Southington",
  "South Windsor",
  "Suffield",
  "West Hartford",
  "Wethersfield",
  "Windsor",
  "Windsor Locks"
)

counts <-
  read_csv(here("data", "raw", "ct_covid_by_town_2026-06-30.csv")) |>
  clean_names() |>
  mutate(
    report_date = mdy(last_update_date),
    town = str_to_title(str_trim(town)),
    total_cases = parse_number(as.character(total_cases))
  ) |>
  filter(town %in% hartford_county) |>
  arrange(town, report_date) |>
  group_by(town) |>
  mutate(new_cases = total_cases - lag(total_cases)) |>
  ungroup() |>
  mutate(new_cases = pmax(new_cases, 0)) |>
  filter(
    report_date >= as.Date("2020-12-01"),
    report_date <= as.Date("2021-01-31"),
    !is.na(new_cases),
    new_cases > 0
  ) |>
  select(town, report_date, new_cases)

That leaves a compact table: for each town and report date, how many new cases showed up. Now we blow it apart.

6.2.2 One row per case with uncount()

tidyr::uncount() is the workhorse of this chapter. Hand it a column of counts and it repeats each row that many times — the exact inverse of count(). A row that says “Hartford, 2020-12-15, 90 new cases” becomes 90 identical Hartford rows.

linelist <- counts |>
  uncount(new_cases) |>
  mutate(case_id = sprintf("HC-%06d", row_number()))

Each row is now one case. They’re still identical within a town-day, so the last step is to give each one an identity.

6.2.3 Inventing values with set.seed() and random draws

To fill in age, sex, and the rest we draw values at random from distributions we pick. sample() draws from a set of categories with given probabilities; rnorm() draws numbers from a bell curve; rbinom() flips weighted coins (hospitalized or not, died or not).

Random draws are different every time you run them — which would make the dataset impossible to reproduce. set.seed() fixes the random number generator so every draw comes out the same on every run. Set it once, at the top, before any drawing happens.

set.seed(20210101)
NoteA cleaner seed is coming later

set.seed() changes the random state for the rest of your session, which is fine in a one-shot script like this but can surprise you in a longer analysis. The reproducibility chapter will introduce withr::with_seed(), which sets a seed for just one expression and then puts the random state back the way it found it — the tidier tool when you only want one block of code to be reproducible. For a standalone data-generation script, plain set.seed() at the top is perfectly good.

With the seed fixed, every field is one mutate() away. A few patterns worth naming:

  • A number from a distribution — age from a bell curve centered on 42, clamped to a human range with pmin()/pmax():

    age = pmin(pmax(round(rnorm(n, mean = 42, sd = 22)), 0L), 100L)

  • A category with set odds — sample() with a prob vector. These proportions are illustrative, not measured:

    sex = sample(c("Female", "Male"), n, replace = TRUE, prob = c(0.51, 0.49))

  • A weighted coin flip that depends on another column — case_when() builds an age-dependent probability, then rbinom() flips it. Hospitalization risk climbs steeply with age:

    hosp_prob = case_when(
  age < 18 ~ 0.01,
  age < 50 ~ 0.02,
  age < 65 ~ 0.06,
  age < 80 ~ 0.15,
  TRUE     ~ 0.30
)
hospitalized = if_else(rbinom(n, 1, hosp_prob) == 1, "Yes", "No")

  • A date relative to another date — onset happens a few days before the report; subtract a random number of days:

    onset_date = report_date - sample(3:14, n, replace = TRUE)

The full script layers a handful of these together, drops the intermediate probability columns, and writes the result with write_csv(). That’s the whole trick: real counts decide how many rows, random draws decide what’s in them.

6.3.1 Categorizing a continuous variable

Age as a raw number is hard to tabulate — you rarely want a row for every single year. Collapsing it into groups is a job for case_when(), reading top to bottom and stopping at the first match:

linelist <- linelist |>
  mutate(
    age_group = case_when(
      age < 18 ~ "0-17",
      age < 50 ~ "18-49",
      age < 65 ~ "50-64",
      age < 80 ~ "65-79",
      TRUE ~ "80+"
    )
  )

count(linelist, age_group)
# A tibble: 5 × 2
  age_group     n
  <chr>     <int>
1 0-17       4602
2 18-49     17627
3 50-64      7579
4 65-79      3885
5 80+        1529

6.3.2 Recoding values

hospitalized and died arrived as "Yes"/"No" text. For counting that’s fine, but for modelling later you’ll often want a clean logical. if_else() recodes a single variable in one line:

linelist <- linelist |>
  mutate(
    hospitalized_flag = if_else(hospitalized == "Yes", TRUE, FALSE),
    died_flag = if_else(died == "Yes", TRUE, FALSE)
  )

count(linelist, hospitalized, hospitalized_flag)
# A tibble: 2 × 3
  hospitalized hospitalized_flag     n
  <chr>        <lgl>             <int>
1 No           FALSE             33319
2 Yes          TRUE               1903

6.3.3 Doing arithmetic on dates

Subtracting one date from another gives a number of days. Two classic epi measures fall straight out of that:

  • Reporting delay — how long from symptom onset to the case being reported.
  • Length of stay — how long a hospitalized patient was admitted.
linelist <- linelist |>
  mutate(
    reporting_delay = as.integer(report_date - onset_date),
    length_of_stay = as.integer(hosp_discharge_date - hosp_admit_date)
  )

linelist |>
  summarise(
    median_delay = median(reporting_delay),
    median_stay = median(length_of_stay, na.rm = TRUE)
  )
# A tibble: 1 × 2
  median_delay median_stay
         <dbl>       <int>
1            8          12

length_of_stay is NA for anyone who was never admitted, which is exactly right — there’s no stay to measure. That’s why na.rm = TRUE is needed in the summary.

6.3.4 Selecting a date range

Filtering to a window is the same filter() you already know, with date comparisons. Say you only want cases reported in the first two weeks of December:

linelist |>
  filter(
    report_date >= as.Date("2020-12-01"),
    report_date <= as.Date("2020-12-14")
  ) |>
  nrow()
[1] 9409

6.3.5 A quick sanity check

Before trusting any built dataset, look for values that can’t be real. Ages should sit between 0 and about 120; onset should never come after the report. A filter() that returns zero rows is a clean bill of health:

linelist |>
  filter(age < 0 | age > 120 | onset_date > report_date) |>
  nrow()
[1] 0

Zero out-of-range rows — no surprise, since we built the data to behave, but on real data this is the check that catches a birth year of 1850 or a typo’d date.

6.3.6 Does it match the real counts?

The whole point of anchoring to real data is that the totals should line up. The synthetic line-list has one row per real case in the window, so its row count equals the real number of new cases Hartford County recorded from December 2020 through January 2021:

nrow(linelist)

linelist |>
  count(town, name = "cases") |>

6.4 Wrap-up

You started with a published count table and ended with a case-level line-list you can slice by age, date, and outcome. More importantly you practiced the manipulation moves that show up everywhere: uncount() to go from counts to rows, case_when() to recode and categorize, seeded random draws to fill in values reproducibly, and date arithmetic to turn two dates into a meaningful number. The next chapters lean on exactly these skills — now on data that finally has a person in every row.
