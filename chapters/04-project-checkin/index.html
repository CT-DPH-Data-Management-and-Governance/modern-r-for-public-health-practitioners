12  Checkpoint: Where the Project Stands

Packages covered in this part: fs, glue

No new package today, no new geometry or verb to learn. This far in, it’s worth stopping to combine everything you’ve built so far into one thing the Commissioner could actually read.

12.2 This week’s briefing summary

Charts are great for a slide deck, but sometimes the Commissioner just wants the numbers in a sentence, right now, before the meeting starts. That’s today’s artifact: a short status paragraph built entirely from skills you already have — dplyr to find the numbers, lubridate to know which date counts as “now”, and glue to turn it into English.

latest_date <- max(covid_clean$last_update_date)
days_of_data <- as.numeric(latest_date - min(covid_clean$last_update_date))

statewide_latest <-
  covid_clean |>
  filter(last_update_date == latest_date) |>
  summarise(
    total_cases = sum(total_cases, na.rm = TRUE),
    total_deaths = sum(total_deaths, na.rm = TRUE)
  )

hartford_latest <-
  covid_clean |>
  filter(town == "Hartford", last_update_date == latest_date) |>
  select(total_cases, total_deaths)
briefing_summary <- glue(
  "Status as of {latest_date} ({days_of_data} days of data collected):\n",
  "Statewide: {format(statewide_latest$total_cases, big.mark = ',')} total cases, ",
  "{format(statewide_latest$total_deaths, big.mark = ',')} total deaths.\n",
  "Hartford: {format(hartford_latest$total_cases, big.mark = ',')} total cases, ",
  "{format(hartford_latest$total_deaths, big.mark = ',')} total deaths."
)

briefing_summary
Status as of 2022-06-24 (822 days of data collected):
Statewide: 822,459 total cases, 11,032 total deaths.
Hartford: 33,844 total cases, 417 total deaths.

Four lines of code, no new concepts, and a paragraph that’s actually correct as of whatever the latest date in the file happens to be — because it’s computed, not typed in by hand.

12.2.1 Saving the checkpoint artifact

write_lines(
  briefing_summary,
  here("outputs", "tables", "briefing_summary.txt")
)

That text file is this checkpoint’s deliverable, the same way a chart was chapter 3’s — a small, real thing that lives in the project folder and didn’t exist before today.

12.3 What your project folder should look like now

fs::dir_tree(here::here(), recurse = 2)

If you’ve been following along in your own covid-briefing/ project, you should see something close to this:

covid-briefing/
├── data/
│   ├── raw/
│   │   └── ct_covid_by_town_2026-06-30.csv
│   └── processed/
│       └── covid_clean.csv        # if you uncommented the write_csv() in ch. 2
├── R/
├── scripts/
├── outputs/
│   ├── figures/
│   │   ├── hartford_new_cases.png
│   │   ├── hartford_vs_state_trend.png
│   │   └── statewide_positivity_map.png
│   └── tables/
│       └── briefing_summary.txt
└── docs/

If your folder looks different, that’s fine — the point isn’t to match this tree exactly, it’s to notice that the folder is filling up with real artifacts instead of staying empty. That’s what progress looks like in a data project: not lines of code, but files someone else could open and use.

12.4 What’s still manual

Being honest about the current state of things:

  • Every chapter’s project re-runs the cleaning steps by hand, from the top, in a .qmd file. Nothing here is a function you could call twice.
  • The raw CSV is a snapshot someone downloaded once. Nothing fetches new data automatically.
  • “Hartford” and the current date are typed directly into the code. Asking about a different town means editing the script, not passing an argument.
  • There’s no history of any of this yet — if you overwrite a file by accident, it’s just gone.

None of that is a problem yet — it’s normal for a project this size. It becomes a problem the day someone asks for the same briefing next week, for a different town, without you sitting at the keyboard.

12.5 What’s next

The parts ahead exist to close exactly those gaps:

  • Managing Code — version control, so every change to this project is recorded, reversible, and explainable to someone other than you.
  • Intermediate R: Automating the Manual Steps — turning repeated code into functions, and pulling fresh data straight from the state’s API instead of re-downloading a CSV by hand.

The scenario hasn’t changed: the Commissioner still wants to know if it’s getting worse in Hartford. What changes from here is how much of the answer you have to rebuild yourself every time someone asks.
