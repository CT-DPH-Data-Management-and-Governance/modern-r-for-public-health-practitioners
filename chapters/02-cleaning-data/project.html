5  Cleaning the Full Report

The Commissioner liked the Hartford briefing. The next ask: stop picking one town by hand and clean the whole report properly, so any town’s numbers can be pulled on demand without redoing the work.

5.1 Setup

library(dplyr)
library(readr)
library(here)
library(janitor)
library(tidyr)
library(stringr)
library(lubridate)
library(glue)

covid_data <- read_csv(here("data", "raw", "ct_covid_by_town_2026-06-30.csv"))

5.2 Step 1 — Clean every column name at once

Chapter 1 renamed a handful of columns by hand with select(). That works for one town and four columns; it does not scale to every column in the dataset. clean_names() fixes all of them in a single call.

covid_clean <-
  covid_data |>
  clean_names()

covid_clean <-
  covid_clean |>

5.4 Step 3 — Guard the town names with stringr

The town names in this file are already tidy, but a report that gets re-downloaded every week shouldn’t depend on that staying true. Trimming whitespace and standardizing case costs nothing when the data is already clean, and saves a debugging session the week it isn’t.

covid_clean <-
  covid_clean |>
  mutate(town = town |> str_trim() |> str_to_title())

5.5 Step 4 — Daily new cases, for every town

Chapter 1’s caveat about “as reported” data applies here at full scale. total_cases is cumulative, so a daily new-case number means computing total_cases - lag(total_cases) again — but this time across 169 towns at once, which means grouping by town first. Without the group_by(), lag() would subtract the last row of one town from the first row of the next.

covid_clean <-
  covid_clean |>
  arrange(town, last_update_date) |>
  group_by(town) |>
  mutate(new_cases = total_cases - lag(total_cases)) |>
  ungroup()

Same reporting caveat as before applies here too — a revised total can still make new_cases negative for a town on a given day. That’s the data, not a bug in this pipeline.

5.6 Step 5 — Scope to the latest report

latest_date <- max(covid_clean$last_update_date)

this_week <-
  covid_clean |>
  filter(last_update_date == latest_date)

nrow(this_week)
[1] 169

5.7 Step 6 — Generate a one-line summary per town with glue

This is the payoff. Instead of a Commissioner asking “what about Stamford?” and someone re-running a filter by hand, every town already has a ready-made sentence.

town_lines <-
  this_week |>
  mutate(
    line = glue(
      "{town}: {total_cases} total cases ({new_cases} new), {total_deaths} deaths"
    )
  ) |>
  select(town, line)

town_lines |>
  filter(town %in% c("Hartford", "New Haven", "Bridgeport")) |>
  pull(line)
Bridgeport: 42752 total cases (27 new), 450 deaths
Hartford: 33844 total cases (22 new), 417 deaths
New Haven: 35872 total cases (24 new), 289 deaths

5.8 Step 7 — A weekly trend appendix with tidyr

The Commissioner also wants to see the trend, not just the latest snapshot, for the state’s largest cities. floor_date() groups rows into weeks, and pivot_wider() lays those weeks out as columns — a compact table that reads left-to-right like a trend line.

cities_of_interest <- c("Hartford", "New Haven", "Bridgeport", "Stamford", "Waterbury")

weekly_trend <-
  covid_clean |>
  filter(town %in% cities_of_interest) |>
  mutate(week = floor_date(last_update_date, "week")) |>
  group_by(town, week) |>
  summarise(avg_new_cases = mean(new_cases, na.rm = TRUE), .groups = "drop")

weekly_trend |>
  pivot_wider(
    names_from = week,
    values_from = avg_new_cases,
    names_prefix = "week_of_"
  ) |>
  clean_names()

5.9 Putting it together

Each step above modified covid_clean and saved it back. Written as one pipeline, the whole cleaning pass is:

covid_clean <-
  covid_data |>
  clean_names() |>
  mutate(
    last_update_date = mdy(last_update_date),
    town = town |> str_trim() |> str_to_title()
  ) |>
  arrange(town, last_update_date) |>
  group_by(town) |>
  mutate(new_cases = total_cases - lag(total_cases)) |>
  ungroup()

5.10 Saving our data artifact

# write_csv(covid_clean, here("data", "processed", "covid_clean.csv"))

Every future chapter can now start from covid_clean instead of re-deriving it — one clean pass, reused everywhere.
